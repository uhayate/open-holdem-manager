### Steal 表把 CO 算进合计，却不给 CO 列（用户发现，判断正确）
- 现象：`Stats` 页 STEAL 区块左表（Steal / Fold to 3Bet / 4-Bet / 4-Bet-Fold），列头只有 `Tot / BTN / SB`。
  **TOT 反而比每一项都低**（38.9% < BTN 44.6% / SB 45.7%），用户因此察觉不对。
- 根因：定义含 CO，显示层没有 CO 列。
  - `backend/app/stat_flags.py:167`：`position in ("CO", "BTN", "SB")` 才置 `steal_opp`。
  - `backend/app/stats_engine.py:20`：`STEAL_POSITIONS = ["CO", "BTN", "SB"]`。
  - `frontend/src/components/stats/StatsCard.tsx:83`：`headers={['Tot', 'BTN', 'SB']}` —— **唯一渲染处，缺 CO**。
- 实测（Hero 5809 手，用库副本 `compute_hero_stats` 复算）：
  `CO opp 619 / BTN 462 / SB 300`，`TOT opp 1381 = 三者之和` ✓。
  TOT 38.9% 被最弱的 CO(31.3%) 拉低 —— 这正是「合计低于分项」的原因。
- **不止 Steal 一行**：`stats_engine.py:305-307` 里
  `fold_to_3bet_steal` / `four_bet_steal` / `four_bet_fold_steal` 的 positions 参数是 `["BTN","SB"]`（不含 CO），
  但它们的 `total` 走全表 `tot[...]`，而分子分母 flag（`steal_attempted` / `steal_faced_3bet`）**都含 CO**
  → **Total 含 CO、分列不含，左表 4 行全部口径不一致**。实测 `fold_to_3bet_steal.total` sample=88，
  而 btn 30 + sb 14 = 44，差额 44 就是 CO。
- 修法（建议，**待用户确认 steal 是否该含 CO**）：
  加 CO 列 → `headers=['Tot','CO','BTN','SB']`，每行补 `sc(stats.X.co, 'co', ...)`；
  同时把那三处的 positions 从 `["BTN","SB"]` 扩成 `["CO","BTN","SB"]`，否则新列是空的。
  `stats.steal.co` 本来就已算好（31.3% / 619），**不用动定义层**。
- 备选（如果结论是不该含 CO）：要改 `stat_flags.py:167` + `STEAL_POSITIONS` 两处，会牵动 `faced_steal` 标记，影响更大。

### 动作金额 2.5bb 被舍成 3（用户发现，判断正确）
- 现象：`Hands` 页 ACTIONS 列，Hero/CO open 2.5bb 显示成 `R3`（右边 replayer 明写 `CO Open 2.5`）。
- 根因：**前端精度档位**，不是后端。`frontend/src/components/hands/Actions.tsx:11-16`：
  ```js
  function formatValue(v: number, precision: number): string {
    if (precision === 0) return Math.round(v).toString();   // 2.5 -> 3
    ...
  }
  ```
  后端 `api/hands.py:211` 已经把金额 round 到 1 位（`v = round(amt_bb_f, 1)`），传过来就是 2.5。
- 那个开关：`HandExplorer.tsx` 的 `bbPrecision`（表头可点击切换，tooltip 写 `rounded` / `1 decimal`），**默认 0**。
  同一开关还控制 POT 列（`Math.round(h.flop_pot)` 等，HandExplorer.tsx:329/343/357）。
  也影响 tooltip：`actionTitle()`（Actions.tsx:19-27）。
- 影响面：所有 R/B/C 金额。开池 **2.5bb → R3**、**3.5bb → R4** —— 恰好是扑克最常见的两个尺度，最容易误读。
- **调用点全清单**（用户随后在 Sessions 页看到同一现象，是同一根因的第二处，不是新 bug）：
  - `HandExplorer.tsx:320/334/348/362`（Hands 页）—— 传 `precision={bbPrecision}`，**有**表头切换。
  - `SessionsPage.tsx:565/574/583/592`（Session 详情页的手牌列表）—— **没传 `precision`**，
    吃 `Actions.tsx:29` 的默认值 `0`，而且这一页**根本没有切换开关**，用户无法自救。← 比 Hands 页更糟
  - `HandDrawer.tsx` → `HandActions.tsx:57` 是**另一套**组件，用 `toFixed(1)`，显示正常，**不受影响**。
  - 结论：改 `Actions.tsx` 一处即可覆盖两个页面；但 SessionsPage 没有 toggle，
    若只是「改默认值」，得顺手确认它是否也该有个开关（或干脆固定 1 位）。
- 修法选项（**待用户定**）：
  (a) 默认改成 1 位小数 —— 最小改动。`precision=1` 的逻辑（`toFixed(1)` + 去尾零）本来就把 `6.0`→`6`、`2.5`→`2.5`；
  (b) 「rounded」档改成「非整数保留 1 位、整数不带 .0」—— 实际等于取消这一档；
  (c) 动作金额固定 1 位、POT 仍按 rounded —— 两列解耦。
  **我倾向 (a)**。
- 现场缓解：点表头的 Precision 切到 `1 decimal` 就能看到 2.5（但默认值仍该改）。

## 手牌表在窄窗口下溢出（用户报，已修，未提交）

- **根因（第二轮才找到，跟第一轮的猜测不同）**：
  `ui/sidebar.tsx::SidebarInset` 的 className 是 `flex w-full flex-1 flex-col` —— **缺 `min-w-0`**。
  flex item 的 `min-width` 默认 `auto` = 内容最小宽度，所以**任何一张宽表都会把整个内容区撑破**，
  进而把 `body` 撑出横向滚动条。表格自己的 `overflow-x-auto` 因此形同虚设（它被撑到了 879px）。
  实测：1080 视口下 `sidebar=256 / sidebar-inset=911`（可用只有 809），`pageOverflow=199`。

  实测证明隐藏列救不了——**页面级溢出与表格列数无关，是 flexbox 的 `min-width:auto`**。
- 修法：
  - `sidebar.tsx`：`SidebarInset` 加 `min-w-0`（**真正的根因修复，影响全站所有页面**）

## Range 页悬停闪烁死循环（提交 be51d96）
- **现象**：鼠标停在 Biggest Leaks 的 QQ 上，屏幕狂闪。
- **根因（自反馈循环）**：`RangePage.tsx` 里 combo 详情卡和 Biggest Leaks / Top Winners 在同一纵向流，
  而 leaks 列表行自己带 `onMouseEnter/onMouseLeave`：
  悬停 → 详情卡渲染（高度从 ~50px 跳到 ~206px）→ 下面的列表整块下移 → 该行从鼠标下滑走
  → mouseleave → 详情卡撤掉 → 行回到鼠标正下方 → mouseleenter → **无限循环**。
  Top Winners 在最下面、往下没内容，所以不闪；Range 格子在左侧 grid 里不受右栏高度影响，也不闪。
- **踩过的两次弯路**：
  1. 先给两种状态都加 `min-h-[176px]` —— 不够。内容比预留值高时卡片照样撑开，位移仍在。
  2. 再试「占位文案做成绝对定位覆盖层」—— 也不行。空态卡片里没有内容，高度直接塌成 24px。
  **正解：让卡片永远渲染同一套结构（固定 9 行 `DetailRow`），空态只把 label 清空、value 填 `—`**，
  高度由结构决定，与 hover 完全解耦。另外原来 `mb-1.5` / `mb-2` 也不一致（6px vs 8px），
  顺手统一成 `mb-2`。
- **通用教训**：**列表项自带 hover handler，而它的位置/尺寸会被自己的 hover 副作用改变 → 必然死循环。**
  凡是这种情况，一律从「让布局与 hover 状态解耦」入手，不要靠调 min-h 猜数字。
- 产物校验：`index-CzpMOgeI.js` 12:40，dist 与 release 一致。

## Range 闪烁第三轮：行间缝隙导致三段跳变（提交 3d09943）★真正的根因
- 前两轮（be51d96 / 9e8fdb5）修的都是**卡片高度**，方向对但不完整 —— 用户仍闪。
- **真正根因**：列表行用 `space-y-2` 隔开，**8px 缝隙不属于任何一行**。
  每行各自 `onMouseEnter`/`onMouseLeave`，于是 QQ → 缝隙 → ATo 会产生
  `hovered='QQ'` → `hovered=null`（详情卡变空）→ `hovered='ATo'` 的**三段跳变**。
  用户看到的就是这个「闪」，跟高度无关。
- **修法**：`onMouseOver` 委托到列表容器，用 `closest('[data-combo]')` 取 combo，
  行上打 `data-combo={c.combo}`。**鼠标在缝隙里移动不触发任何事件，`hovered` 保持不变**，
  直接从 QQ 划到 ATo 只触发 ATo 那一次。leaks 和 winners 两个列表都有同样隐患，一起改。
- **通用教训**：列表项之间有 `gap`/`space-y` 时，**不要在每行上配 enter/leave 配对**。
  缝隙必然产生 null 状态。改用容器委托 + `closest()`，或给容器加 `onMouseLeave` 只做收尾。
- 前两轮的修复本身不是错的（高度统一确实需要），但**我应该先问「闪」是抖动还是跳变**，
  一上来就假定是布局问题，浪费了两轮打包。**现象描述要先分类再定位。**
- 产物校验：`index-CIAww1wI.js` 12:59，dist 与 release 一致。

## Range 高度第五轮：两态 DOM 结构不等价（提交 c654cbe）★用户亲自指出
- 用户判断「明细一开始没有成功高度占位」是对的。**根因不是缺 min-h，是两态渲染的 DOM 不同**：
