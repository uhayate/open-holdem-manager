## 打包残留更新产物：`publish: null` 才是开关（提交 9f5cbf5）
- 用户要求删掉更新系统（怕指向 fork 源项目），我删了 `publish: provider: github`，
  **但打出来的包里 `resources/app-update.yml` 还在**。我原先的判断「删掉 publish 块就不生成」是**错的**。
- 真机制（`app-builder-lib/out/publish/PublishManager.js`）：
  - `getPublishConfigs()` 只在 `publish === null`（**显式 null**）时返回 `null`；三处任一处即可
    （`nsis.publish` / `win.publish` / 顶层 `build.publish`）。
  - **`publish` 缺失（`undefined`）≠ 不发布** → 掉进 `getPublishConfigsForUpdateInfo()` 的兜底：
    `packager.info.repositoryInfo`（即 package.json 的 `repository` 字段）是 github 就自动推断 provider，
    然后照样写 `app-update.yml`。源码注释原话：
    *"default publish config is github, file should be generated regardless of publish state"*。
  - **结论：必须写 `publish: null`，删掉这个键是反效果。** schema 允许 null（`{"type":["null","string"]}`）。
- `.blockmap` 开关是 `nsis.differentialPackage`（`isBuildDifferentialAware = !isPortable && differentialPackage !== false`）。
  它只服务于 electron-updater 的差分更新。设 `false` 后：`.blockmap` 消失，**且恢复 solid 7z 压缩**
  （差分感知会强制 `solid=false, dictSize=1`）→ **安装包 126.4MB → 113.6MB，-12.8MB（-10.1%）**。
- 另外确认：`app-update.yml` 里 owner 是 **`uhayate`**（用户自己的 fork），不是 AHTOOOXA ——
  「指向原项目」从内容上没发生，但文件本身仍属死代码（源码已无 `electron-updater`/`autoUpdater` 消费者）。
- 验证脚本要点：`ls release/*.blockmap` 不存在时 `&&` 链会断，**检查多个可选文件要用 `;` 不要用 `&&`**。
