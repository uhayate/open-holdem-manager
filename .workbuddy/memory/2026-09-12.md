## 修掉「应用关闭硬杀后端」——坏 WAL 的源头（commit `db583e7`）

用户拍板「你改吧」。这是坏 WAL 的**根本成因**，之前一直没动是因为 GUI 退出路径难验证。

**根因**：`electron/main.js::killBackend()` 用 `child.kill()`，Windows 上 = `TerminateProcess` → Python `atexit` 不跑 → `close_db()` 不跑 → DuckDB 不 checkpoint → 留半截 WAL。而重建/导入期间故意设 `checkpoint_threshold='10GB'`，所以**首启重建时关窗口 = 大概率产出坏 WAL**。

**设计上最关键的一点（别漏）**：光加 `POST /api/shutdown` 不够。`_run_rebuild_sync`、`_process_hands`、`import_files_stream` **全程持 `db_lock`**，而 `close_db()` 也要 `_lock` → 不中断的话 uvicorn 的 shutdown 会一直卡到任务跑完 → 超过 electron 超时 → 照样强杀。**必须让长任务能中断。**

**改动**：
- `db.py`：新增 `_shutdown_requested`(Event) / `request_shutdown()` / `shutdown_requested()` / `ShutdownInterrupted(RuntimeError)`。
- `import_hands.py`：三处轮询——`_run_rebuild_sync` 逐手、`_process_hands` 逐手、`import_files_stream` 逐批；新增 `_abort_import(db)`（`ROLLBACK` + **重建被 drop 掉的索引**，因 `_drop_indexes` 在事务外，回滚不会恢复它）。用户触发的 `_bg_rebuild` 补上 `except ShutdownInterrupted` 分支 + 失败时的 `ROLLBACK`（原来缺）。
- `main.py`：`POST /api/shutdown` → `request_shutdown()` **然后** `server.should_exit = True`（顺序重要：先置标志，重建才会在 uvicorn 开始 shutdown 前就退出）。dev 下无 `uvicorn_server` → 返回 `{"status":"no-server"}`。**命名注意**：已有 `@app.on_event("shutdown") def shutdown()`，接口函数只能叫 `shutdown_server`。
- `run_server.py`：`uvicorn.run(app,...)` → `uvicorn.Server(uvicorn.Config(...))` 并把实例挂 `app.state.uvicorn_server`（`uvicorn.run` 会把实例私有化，请求处理器就没法停服务）。
- `electron/main.js`：`SHUTDOWN_TIMEOUT_MS=15000`；`stopBackend()` = POST `/api/shutdown` → `Promise.race(exit, 15s)` → 超时才 `killBackend()`；`before-quit` 用 `preventDefault()` 接管（`quitting` 守卫二次进入），`window-all-closed` 只 `app.quit()`；`install-update` 先 `await stopBackend()` 再 `quitAndInstall`（避免更新成为唯一跳过 checkpoint 的路径）。
- `CLAUDE.md`：Hard-Won Invariants 补 3 条 + 新增 "Shutdown" 一节。
- `backend/tests/test_shutdown.py`（新，5 例）：标志、endpoint（有/无 server）、重建中断+回滚+索引恢复、`_abort_import`。**注意 autouse fixture 清 `_shutdown_requested`**——它是进程级全局，泄漏会污染其它测试。全套 **37 passed**。

**验证（三层）**：
1. 正常退出：起后端 → `POST /api/shutdown` → 自行退出 exit 0，日志 `Shutting down / Application shutdown complete`，**目录里的 WAL 消失**（退出前 12KB 主库+36KB WAL → 退出后 2.6MB 单文件 = 真 checkpoint 了）。
2. 中断机制（确定性）：预置标志后跑 `_run_rebuild_sync` → 抛 `ShutdownInterrupted`；`ROLLBACK` 后 hands/hand_players/board_cards 计数与 6 个索引**全部还原**，连接仍可用。
3. 并发真实场景：把库放大到 **13140 手**，`rebuilding:true (processed 0/13140)` 时发关闭 → **2 秒自行退出、exit 0、无 WAL**，日志有 `app.db.ShutdownInterrupted: app is shutting down; rebuild aborted`，`stat_version` 仍为 1（= 中断而非跑完）。打包后的 exe 同样验证通过（health 200 → 关闭 → 1s 退出 → WAL 消失）。

## 🐛 关窗口弹 `ReferenceError: quitting is not defined`（commit `73e1a02`）

用户装上新包后**一关窗口就弹**「A JavaScript error occurred in the main process / ReferenceError: quitting is not defined @ main.js:400」。**这是我 `db583e7` 引入的 bug**，而且更糟的是它**完全废掉了那次改动的目的**：handler 在 `preventDefault()` 之前就抛了，所以后端根本没被请求退出 → 还是硬杀 → 还是可能留坏 WAL。

**根因不是「一个拼写错误」**：退出路径引用了**三个从未声明**的标识符：
| 标识符 | 位置 | 用途 |
|---|---|---|
| `quitting` | 400 读 / 406 写 | before-quit 二段守卫 |
| `backendUrl` | 164 / 166 | `requestBackendShutdown()` 要 POST 的目标 |
| `SHUTDOWN_TIMEOUT_MS` | 198 | 15s 兜底超时 |

→ **只修 `quitting` 只会把异常往下挪四行**。三个都补上：`let backendUrl` / `let quitting` 放模块状态区，`SHUTDOWN_TIMEOUT_MS = 15000` 作常量；`backendUrl` 在 `whenReady()` 里赋值（否则 shutdown 请求没目标）。另外把 `before-quit` 改成**不可能卡死应用**（`.catch()` 记错后仍 `.finally(() => app.quit())`）。

**为什么会漏掉**：上次我明确写了「GUI 退出路径本会话验证不了」，然后**就那样发货了**。所以这次补两条自动检查，并接进 `npm run build`：

1. **`scripts/check-electron.mjs`**（`npm run check:electron`）—— 用 frontend 的 tsc 跑 `--allowJs --checkJs --noEmit`，**未声明标识符报 TS2304**。拿修复前的版本跑，**精确复现用户那条 `(400,16): Cannot find name 'quitting'`**，外加紧接着会炸的 4 条（`backendUrl`×2、`SHUTDOWN_TIMEOUT_MS`、`quitting`）。顺带给 `findFreePort` 的 `server.address().port` 加了 JSDoc cast（那是唯一残留的 TS2339，纯类型误报）。
2. **`scripts/check-quit-path.cjs`**（`npm run check:quit`）—— 用 stub 的 `electron`/`electron-updater`/`http`/`child_process`（覆写 `Module._load`）**真加载 `electron/main.js`**，然后 `app.emit('window-all-closed')`。6 条断言：不抛异常、无启动错误框、**恰好一次 POST `/api/shutdown`**、**`child.kill()` 为 0**、`before-quit` 恰好 defer 一次、最终 `quitCompleted === 1`。
   - 关键设计：`app.quit()` stub **模拟真实 Electron 语义**（emit `before-quit`，`preventDefault()` 则中止退出）——这正是我上次不敢确定、也是最该被测的一点。
   - 支持 `node scripts/check-quit-path.cjs <某份 main.js>` 指向别的副本，**用来证明这个 harness 真的抓得住回归**：对修复前版本跑 → 4 项 FAIL + `thrown: ["ReferenceError: quitting is not defined"]`，与用户截图完全一致。
