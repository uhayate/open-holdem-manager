### 锦标赛导出与现金桌的 3 处结构性差异（每一处都会让第一行就失败）
| 项 | 现金 | MTT |
|---|---|---|
| header | `Hold'em No Limit ($0.01/$0.02)` | 盲注挪进 level tag：`- Level13(350/700(85))`，`$` 只出现在**买入额**上（`Daily Hyper $1`） |
| 金额符号 | `collected $1.61 from pot` | `collected 13,906 from pot`（筹码，无 `$`） |
| 千分位 | 无 | `13,906` / `(5,266 in chips)` |

header 形如：
`Poker Hand #TM6224769827: Tournament #300704318, Daily Hyper $1 Hold'em No Limit - Level13(350/700(85)) - 2026/07/26 21:28:22`

写法：`_AMT = r"\$?([\d,]+(?:\.\d+)?)"` 拼所有金额正则 + `_dec()` 剥逗号；**别手写 `\$([0-9.]+)`**（会静默拒绝全部锦标赛手牌）。
MTT 的 `bb_amount` 必须直接取 level tag —— `_detect_bb` 是给"字节损坏的现金 header"投票纠错的，会把 350/700 snap 成标准值。
`stakes` 用 `"MTT 350/700"`，否则 `formatStakes` 会算成 `NL70000`。

### 两条独立于实现的硬结论
1. **MTT 的 bb/100 没有意义**：盲注每几手涨一次，`won_bb` 把 100bb 的早期筹码和 10bb 的后期筹码相加。
   4035 手算出来 +29.6 bb/100，纯废数字。**VPIP/PFR/3bet/位置频率才是可信的。**
2. **`db.py::init_schema` 的 game_mode 白名单会抹掉新模式**：
   原来最后一条是 `UPDATE hands SET game_mode='' WHERE game_mode NOT IN ('', 'Fast Fold')`，**每次启动都跑**
   → 新增的 `'MTT'` 导完正常、重启就消失。修法是先归一化未知值，再按 ID 前缀只回填**空值**。
   这个坑只在"打包版 + 重启"路径上暴露，源码里导入完立刻查是好的。
