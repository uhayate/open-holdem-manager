## MTT 手牌导入（commit `e7bcc82`）

用户报"导入 MTT 报错"，截图全是 `Cannot parse header line: Poker Hand #TM…: Tournament #…, Daily Hyper $1 …`。
样本目录 `C:\Users\uhayate\Desktop\手牌记录\MTT`（63 个文件 / 4035 手）。

**根因**：解析器只认现金桌格式。锦标赛导出有 3 处结构性差异，每一处都足以让第一行就失败：

| 项 | 现金 | MTT |
|---|---|---|
| header 盲注 | `Hold'em No Limit ($0.01/$0.02)` | 盲注挪进 level tag：`- Level13(350/700(85))`，`$` 出现在**买入额**上 |
| 金额符号 | `collected $1.61 from pot` | `collected 13,906 from pot`（筹码，无 `$`） |
| 千分位 | 无 | `13,906` / `5,266 in chips` |

`RE_HEADER` 早就有 `(?:Tournament #\S+, )?` 的半截兼容，但 `Daily Hyper $1 ` 这段名字卡在中间 → 从不匹配。
`detect()` 倒是已经列了 `TM`，所以文件被认成 GG，然后逐手报错。

**改法**（`parsers/ggpoker.py`）：
- 新增 `_AMT = r"\$?([\d,]+(?:\.\d+)?)"` 与 `_dec()`，**所有**金额正则由它拼、所有捕获值过 `_dec()` 剥逗号。
  共 23 处 `Decimal(x.group(n))` → `_dec(...)`。以后别再手写 `\$([0-9.]+)`。
- 新增 `RE_HEADER_MTT`，`RE_HEADER`（现金）先试，失败再走锦标赛分支。
- **MTT 跳过 `_detect_bb`** —— 那个函数是给"字节损坏的现金 header"投票纠错的，会把 350/700 snap 到标准值（$2/$5），直接毁掉。level tag 是权威。
- `stakes = "MTT 350/700"`（筹码不是货币）。否则 `formatStakes` 会算出 `NL70000`。
- `game_mode = "MTT"`。

**顺手修的既有 bug**：游戏模式下拉里选 "Regular" 会传字面量 `__reg__` 给 API → 永远 0 条。
原先 `''` 同时表示"全部"和"Regular"，现在 `undefined` = 全部、`''` = Regular，四页 state 一并改。

**验证**：
- 4035/4035 手解析成功，0 错误，逐手 `sum(won)+fees==0` **0 处破坏**。
- 用真实库副本跑 `_process_hands` 全量导入：4035 手入库，`game_mode='MTT'`，hero 4035 手。
- **回归**：库内 26062 手现金（用户这两天又导了一批，9132 → 26062）重解析后 `stakes/sb/bb/game_mode` **零差异**。

### 顺手挖出并修掉的第二个 bug：启动迁移会抹掉 MTT
`db.py::init_schema` 里回填 game_mode 的三条 UPDATE，最后一条是
`UPDATE hands SET game_mode='' WHERE game_mode NOT IN ('', 'Fast Fold')` —— **每次启动都跑**。
新加的 `'MTT'` 不在白名单里 → 用户导完 MTT、重启一次就全变回 `''`，模式下拉里的 MTT 消失。
**这个 bug 只有在"打包版 + 重启"路径上才暴露**，源码里导入完立刻查是好的（我第一次就差点被骗过去）。
改成：先归一化未知值，再按 ID 前缀只回填**空值**（`WHERE game_mode='' AND id LIKE 'TM%'`），幂等且不覆盖已有模式。

### 必须知道的限制（不是 bug）
**MTT 的 bb/100 没有意义**：每几手涨一次盲注，`won_bb` 把 100bb 的早期筹码和 10bb 的后期筹码混加。
hero 4035 手算出来 +29.6 bb/100，这个数字不能用。**VPIP/PFR/3bet/位置频率是可信的**。
推荐 MTT 单独建 workspace，否则会污染现金的 bb/100 与 population 统计。
